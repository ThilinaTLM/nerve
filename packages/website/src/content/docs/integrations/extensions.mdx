Extensions add optional capabilities to the agent. Each has its own switch, settings, and accounts, and most add a namespace to [Quick script](/guides/quick-script/). Nerve ships five built-in extensions. You can also have the agent [build your own](/guides/build-extensions/): file previews, pages, side panels, themes, and integrations that you review and allow in Settings first. Locations and trust rules are in [Extension locations and trust](/reference/extensions/).

| Extension                               | Adds                                                               | Default | Needs                                         |
| --------------------------------------- | ------------------------------------------------------------------ | ------- | --------------------------------------------- |
| [Atlassian](#atlassian)                 | `jira`, `confluence`, and Confluence page builders in Quick script | Off     | An Atlassian account (site, email, API token) |
| [Web Search](#web-search)               | The `web_search` tool and `search.web` in Quick script             | Off     | A Tavily account (API key)                    |
| [Diagrams](#diagrams)                   | `diagram.render` in Quick script                                   | On      | A Kroki server (the public one by default)    |
| [Image generation](#image-generation)   | `imagegen.generate` in Quick script                                | Off     | A ChatGPT (OpenAI Codex) sign-in              |
| [Image explanation](#image-explanation) | The `explain_image` tool                                           | Off     | A model that can read images                  |

Web fetch isn't an extension. It's always available to Quick script and follows the `web_fetch` tool rules; see [Web search and fetch](/integrations/web/).

## Set up an extension

<Steps>

1. Open **Settings → Extensions** and select an extension. Each row shows how it is set up and has its own switch.
2. If it needs an account, add one under **Settings → Accounts** (name, fields, and secret such as an API token, or sign in in your browser for services that use OAuth). Use **Test connection** where it's offered.
3. Choose that account in the extension's settings, adjust its options, and turn the extension on.
4. Check **Settings → Tools**. Tools such as **Quick script** and **Web fetch** have their own switches, and the Quick script row lists which namespaces are usable or what to fix.

</Steps>

An extension's page shows a problem at the top when it can't be used, with a link to fix it: no account selected, an account that needs sign-in or has no saved secret, or a model that's no longer available. The agent only sees namespaces and tools that are on and usable.

## Scope and trust

- **User** and **project** switches sit side by side on each extension row. The project switch overrides the user one for that project and can be shared through the repository. Anything unset in a project follows your user settings. An [agent profile](/reference/agent-profiles/) can also recommend or require extension settings.
- **Accounts are user-level or project-level.** A user account is available in every project, a project account in one. Their credentials are stored encrypted on your computer and are never copied into project files; a project selects an account by an ID that exists only on your computer, so a teammate must choose their own. Settings at user scope can choose user accounts only. Manage accounts under **Settings → Accounts**; see [Settings at a glance](/guides/settings/#accounts).
- A project's `.nerve/config/extensions.json` is ignored until you trust its exact content. The Extensions page says the file needs your review, with **Review and trust** and **Decline**; a trusted file can be revoked there. Changes you make through Nerve's settings pages stay trusted; an edit made in another editor needs review again.

See [Configuration](/operations/configuration/#extension-settings-and-accounts) for the files.

## Installed extensions

Beyond the built-ins, you or the agent can install extensions as folders: in `<NERVE_HOME>/agent/extensions/<id>/` for every project, or in `<project>/.nerve/extensions/<id>/` for one project and its teammates. The easiest way to make one is to ask a [Forge conversation](/guides/configure-by-chat/) to build it; [Build an extension](/guides/build-extensions/) covers the workflow, and [Extension locations and trust](/reference/extensions/) the rules.

A new extension shows as **Pending consent** in **Settings → Extensions** with a plain-language list of what it asks for. Nothing runs until you choose **Allow**, and the agent can't do that for you. A project extension asks again after any change; a user extension asks again only when it gains a permission or contribution. **Revoke** in the Source section withdraws consent.

{/* screenshot: extension-consent */}

Installed extensions run in a sandbox and can contribute:

| Contribution                         | Where it appears                                                                              |
| ------------------------------------ | --------------------------------------------------------------------------------------------- |
| **Dock panel**                       | A panel beside the conversation, like Git or Files                                            |
| **Page tab**                         | A tab in the center area, opened from the new-tab menu (the chevron next to +)                |
| **File preview**                     | A viewer for chosen file types, in place of the source view; it can offer editing             |
| **Theme**                            | A color theme you pick in **Settings → Workbench**; only user extensions can add themes       |
| **Quick script namespace and tools** | Methods the agent calls in [Quick script](/guides/quick-script/), and optionally direct tools |

Panels, pages, and previews are drawn in isolated frames with no network access of their own. They use Nerve's components, including floating toolbars for previews and canvas-like pages, and reach data only through the extension's backend and the host.

## Accounts

Extensions that talk to a service use **accounts** instead of keys in settings. An account's credentials are encrypted on your computer and the extension's code never sees them; Nerve adds them to requests, only for the account's own websites.

{/* screenshot: accounts */}

- **Levels.** A **user** account is available in every project and a **project** account in one. An account kind defined by a project extension is always project-level. Settings at user scope can choose user accounts only. You can move an account between levels, duplicate it, or clear its credentials.
- **Static keys.** A token, password, or API key you type in. An account can hold several secrets, and Nerve can send one as a bearer token, basic auth, a header, or a query parameter.
- **OAuth 2.0.** Authorization code with PKCE, or device code, with OIDC discovery. Sign-in runs in a browser page or with a device code, inside the account dialog. Nerve ships no OAuth apps, so the extension's account asks for the client ID of one you register with the service.
- **Credential providers.** For request signing (such as AWS SigV4), token exchanges, and other sign-in flows, an extension can bring its own credential code. It runs in a separate sandbox with no free network access, and the review shows it as broad access. Changing it asks you to allow the extension again.
- **Platforms.** An extension can use every account of a platform (for example GitHub) whichever extension defined it. It can narrow the account's websites but never widen them, and consent is per platform.

Add an account from the extension's page (**Add account**), or manage them all on **Settings → Accounts**. A project selects an account by an ID that exists only on your computer, so teammates choose their own. See [Settings at a glance](/guides/settings/#accounts).

### Refreshed in the background

OAuth tokens are refreshed when used, and once more after a 401 response. A background job, **Account credential refresh**, also renews sign-ins that expire within ten minutes every five minutes, for accounts you used in the last 30 days. It appears under **Settings → Background jobs** with its last and next run and **Run now**. An account that needs you to sign in again, or a job that keeps failing, shows in the notification bell. Jobs run only while Nerve runs.

## Atlassian

Jira and Confluence share one Atlassian account.

1. Add an account with your site URL (for example `https://acme.atlassian.net/`), email, and an API token created in your Atlassian account settings. Optional defaults: a Jira project and a Confluence space.
2. Choose the account in the extension and switch on **Jira**, **Confluence**, or both (both are on by default once the extension is on).

The account shows its connection status: verified, credentials rejected, access restricted, not on this site, or couldn't check. See [Jira](/integrations/jira/) and [Confluence](/integrations/confluence/) for what the agent can do.

## Web Search

Add a Tavily account with an API key and select it as the **Search account**. The agent then has `web_search`, and `search.web` inside Quick script. Details are in [Web search and fetch](/integrations/web/).

## Diagrams

Diagrams render with a [Kroki](https://kroki.io/) server and are saved as PNG files in the conversation. The extension is on by default and uses the public server `https://kroki.io/`, which is shared. Diagram source is sent to that server, so enter a self-hosted URL under **Kroki server** for private diagrams.

## Image generation

Choose the **Backend** (OpenAI Codex, which uses your ChatGPT subscription's image access instead of API billing), its **Model**, and default **Quality**. **Size** and **Background** are under advanced settings. A call can override size and backend options such as quality; the saved image is a conversation file the script can resize, attach to a Confluence page, or show you. Generation spends your subscription's allowance. Availability can vary by account.

## Image explanation

For a main model that can't read images. Choose a vision-capable **Model** and a **Thinking level**, then turn the extension on. The agent can then call `explain_image` on a JPEG, PNG, GIF, or WebP file (up to 20 MiB) with an optional focus prompt and gets back a short written description. The image goes only to the model you selected, and its usage is billed separately from your main model. Point it at a local model through a compatible [custom provider](/models/custom-providers/) to keep images on your machine. See [Images and voice](/guides/images-and-voice/).

## Permissions

Extension actions are classified by where they act. **External read** covers reading outside your machine: web search, Jira and Confluence reads, diagram rendering. **External write** covers changes there: creating issues, updating pages, generating images. The built-in Read-only and Planning permission levels allow external reads and deny external writes; Supervised asks for both. In **Settings → Permission rules**, a rule can match these risks, or a Quick script operation such as `jira.issues.*`. See [Choose a profile, model, and permissions](/guides/agent-controls/#choose-a-permission-level).
