Nerve separates a durable **launch definition** from immutable **launch runs**. A definition owns its label, command, working directory, and launch policy. Restarting creates a new run in the same lineage, so the launch and tab remain stable while prior output stays in History.

- `single` (default): launching an active definition focuses its current run.
- `concurrent`: launching can create another active run.

Use finite Bash for commands that should finish. Use `task_start` for a known server or watcher. An explicit `task_start` is detached supervised work: status can appear in the launch UI and transcript, but terminal completion does not restart the agent. By contrast, when a finite Bash call outlives its wait and Nerve automatically promotes it, that promoted command remains awaited work for the originating agent. Nerve delivers its result and can continue the agent after the foreground turn settles. A launch is separate from an agent todo: launches supervise processes, while todos describe work inside a conversation.

Before starting a server or watcher, the agent checks active launches once unless it already knows the current launch state. A successful start reports the new launch and any other active launches in the workspace scope, allowing the agent to notice possible overlap without heuristic duplicate detection.

## Agent tool contract

`task_start` accepts one command and an optional project-relative `cwd`; absolute paths and traversal outside the project are rejected. Readiness is one `ready` object with `kind: "url"`, `"detected_url"`, or `"pattern"`. Agent-started launches publish asynchronous status updates, but the explicit tool remains detached from agent continuation.

Use `task_status({ launches: [idOrName] })` for selected launches, or omit `tasks` to list active launches. Use `task_logs({ launch, mode, cursor })`; `cursor` pages backward in recent/error/warning modes and forward in `since_cursor` mode. Use `task_control({ launch, action })` to stop or restart through Nerve's safe process-tree policy.

## Supervision

A launch can define readiness by URL, first detected URL, or output pattern. The agent receives asynchronous status rather than polling; status and log tools remain available for on-demand diagnosis. Dedicated views provide status and bounded streaming logs with cursor, error, warning, and first-failure modes. Runtime can be capped at up to 24 hours.

Environment values supplied to launch start are encrypted at rest and displayed as redacted keys. They still enter the child process; treat its logs and behavior as sensitive.

## Recovery

Nerve has no persistent sidecar supervisor. On restart it verifies process identity with platform evidence:

- `recovered`: verified live; stop/restart remains available, but old stdout/stderr is frozen because pipes cannot be reattached;
- `interrupted`: verified gone;
- `recovery_unknown`: identity cannot be proven, so destructive PID actions are blocked.

Linux uses `/proc` start identity and process groups; macOS uses process-start fingerprints and groups; Windows uses creation time and process-tree termination. Port discovery is best effort.

A normal **Stop** requests graceful process-tree termination and escalates after a bounded wait. Verified recovered and stuck-stopping runs also offer **Force kill**: immediate for stuck-stopping runs, confirmed for verified recovered runs because you may not have asked to terminate them. After the run is terminal, remove its history or choose **Run saved launch again** to launch the definition's current configuration. Nerve does not force-kill `recovery_unknown` records because their PID identity is unverified.

Quitting the desktop app immediately terminates active local launch process trees before its owned daemon exits. Closing to the tray leaves launches running.

## Launch controls

The Launches panel and task-output tab let you switch between sibling runs, restart a saved launch, cancel a run, load earlier log output, clean up terminal history, and prune old runs. The project switcher also includes running launch counts in its activity state, so work in another project remains visible. The agent uses `task_control` with `action: "stop"` or `action: "restart"` for one launch at a time. **Force kill** is available only when Nerve has verified the process identity (or a run is stuck stopping); it is intentionally unavailable for `recovery_unknown` records. Removing a run's history does not remove the durable launch definition.

## Agent notifications

Launch terminal changes can become deduplicated `task_event` system entries in the conversation. Auto-promoted Bash commands create an awaited obligation for the originating agent; delivery is durable and idempotent, and a settled foreground turn can be continued when the result is ready. Explicit `task_start` processes are detached: their updates remain visible, but terminal completion does not create an obligation or start a fresh agent turn. This is separate from desktop/browser toast notifications.
