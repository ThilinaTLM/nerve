Nerve separates a durable **launch definition** from immutable **launch runs**. A definition owns its label, command, working directory, and launch policy. Restarting creates a new run in the same lineage, so the launch and tab remain stable while prior output stays in History.

- `single` (default): launching an active definition focuses its current run.
- `concurrent`: launching can create another active run.

Use `bash` for commands and `launch` for the user's saved dev servers. Bash can run explicitly in the background or move there automatically after a user-controlled wait. Background runs always notify the conversation on exit. A launch is separate from an agent todo: launches supervise processes, while todos describe work inside a conversation.

Before starting a server, check `launch status` and prefer an existing launch definition. Definitions live in `.nerve/launches/definitions.json`; only the user can create or edit them.

## Agent tool contract

`bash` accepts a command and an optional project-relative or absolute `cwd` inside the project. `background: true` returns at once. Its optional `ready` string is an HTTP(S) URL or a regex matched against stdout and stderr. Readiness waits at most 60 seconds; a timeout does not stop the process.

With auto-promotion enabled, foreground commands still running after the configured wait become async Bash, and `timeout` is not available. With promotion disabled, foreground calls require a timeout in seconds and the process tree is killed when it expires. Background runs have no time limit.

Use `async_bash list` for running commands (`all: true` includes finished runs), `async_bash logs` to inspect output, and `async_bash stop` to terminate a process tree.

Use `launch status` for definitions and their launches. `launch start`, `restart`, and `stop` accept a definition ID or launch ID; a definition ID selects its latest launch for restart, stop, and logs. Restart uses the current definition, starting it if nothing is running.

## Supervision

A `single` definition already running returns its active launch rather than starting another. If a definition declares a port, start and restart wait up to 30 seconds for it to listen. Port conflicts report the listener's PID and process name; agents never terminate foreign listeners.

Both log tools accept a 0-based `offset` and `limit` (default 100, maximum 500). Omitting offset returns the last lines. Large output is summarized with file paths for `read`/`grep`, rather than flooding the conversation context. Status and log actions are reads and never ask for approval; process-changing actions use command policy.

## Recovery

Nerve does not recover processes after a daemon restart. Async Bash becomes `lost`; launch instances are memory-only. Saved launch definitions and log files remain, so inspect the retained output and start the current definition when needed.

Async Bash ends on process exit, `async_bash stop`, conversation stop/delete, or daemon shutdown. Stop terminates the process tree gracefully, then escalates after a bounded wait.

Quitting the desktop app terminates active local process trees before its owned daemon exits. Closing to the tray leaves processes running.

## Launch controls

The Launches panel lets you inspect saved definitions and their runs, start or restart the current definition, stop a launch, and inspect retained output. Agents use the same definitions through `launch`; they cannot create or edit them. A new start or restart creates a new launch without changing the definition's identity.

## Agent notifications

Explicit and auto-promoted background Bash runs always queue an `async_bash_event` completion notice. When a launch started by an agent exits on its own, the starting conversation receives a notice with status, exit code, and a projected output tail. These notices can wake the agent; do not poll for completion. Workbench launch updates to the UI are separate from desktop/browser toast notifications.
