## Converter and durability boundary

- `released-format.ts`: registered pure converters, explicit mode snapshots, catalog/launch split, per-field parent-copy removal, source-preserving skills and child freezing. Missing custom definitions or unestablished skill source identities fail closed instead of guessing. D10 exports exact prompt context into conversation-only JSON fields; working directory relocates onto `conversation`, and `conversation_config` is dropped.
- `released-export.ts`: protected original-byte backups, source-bound durable receipts, collision/readback/retry checks, trust decisions, explicit postcommit retirement and conflict-aware rollback.
- `released-verification.ts`: one valid, role-correct export for every unchanged affected row; no discard bypass.
- `released-metadata.ts`: source-bound planning tool/review metadata DML plan, never arbitrary prose replacement.
- `released-executor.ts`, `released-backup.ts`, `released-archive.ts`: fake-tested transaction/backup/resume state machines, protected online-backup ownership receipts and retained per-attempt archives.
- `released-sqlite.ts`: production adapter; verifies retained context/history/schema/trust against the consistent original snapshot, binds version/checksum, and restores only an unchanged migration candidate.
- `step.ts`: inventories known projects, persists the plan, exports/verifies documents, runs the production backend, and retires legacy sources only after the runner's durable verified marker.
- `released-project.ts`: first-use project conversion uses the same converters with serialized path locks, exact original trust, durable retry receipts and diagnostic failure caching. The global ledger does not cover unseen projects.
- `documents.ts`: registered planning-selector policy rewrites; invalid/future policies remain untouched for their owning health loader. Project-local rule-set directories and UI state are not migration inputs.

Exact SQL, ordering, recovery and validation limits are in `/tmp/p5-migration-diff.md` for this review round. Production execution is approved under D13 after copied-slot validation; fake tests alone are not equivalent to that rehearsal evidence.

Trust retains `project_capabilities` for scoped tool/skill policy identity and carries `subagent_profile` → `agent_profile`. No new kind is added. Only a matching original path, project, kind, digest and trusted status can grant converted bytes; converted untrusted originals remain rejected. Re-grants are reported. This intentionally replaces the old blanket profile rejection.

Converter/export/executor tests use plain objects and in-memory file maps; `conversation-context.test.ts` uses a fake SQL driver, not SQLite. Runtime repositories retain working directory on `conversation`, not a config table; history allows unknown JSON prompt/agent fields, while each execution captures validated conversation context and separate profile instructions. The conversation rebuild preserves every released constraint/index and verifies inbound foreign keys. Disposable summary-cache list/snapshot/event merges are display-only. Released step 0001 already has its own frozen `storage.ts`/schema boundary; none of its files were edited. Fresh core SQLite initialization and profile-transition tests run normally.
