# Scoped storage core (not wired)

`ScopedDocumentStore<Scope, Document>` is a low-level store for revisioned domain documents. Construct one per domain with a stable user/project/conversation path resolver, required-file predicate, strict parser, supported version, empty optional document factory and redacted parser-error classifier. Construction does no IO. Only `ensureLoaded(scope)` and explicit recovery `reload(scope)` read authoritative documents; cached failures are also lazy/memoized. Missing optional documents remain unwritten, revision `0`, digest `"missing"`. Required documents are never manufactured.

## API

Profile-definition domains may set `revisioned: false`: no revision is synthesized or persisted, and the internal generation's revision slot is zero (callers edit by digest only). `create(scope, completeDocument)` explicitly creates a missing target under the same serialization/check/write/publication protocol; it rejects existing targets and requires revision one for revisioned documents. This is a trusted creation primitive, never an automatic fallback for a required missing document or an invalid-document repair.

- `ensureLoaded`, `reload`, `peek`: discriminated health (`ready`, `missing-optional`, `unavailable`) and immutable complete generations. Unavailable health is not executable configuration. `retainOnInvalid` explicitly exposes an old generation for **non-security** consumers only; post-persist publication failure never retains one.
- `save(scope, {revision, digest}, change)`: serialize read/check/change/write/publication, compare both loaded identity and current exact file bytes, validate, increment revision, atomically persist, synchronize the parent directory and synchronously publish/invalidate before acknowledging. Returns generation and directory durability (`synchronized` or `unsupported`). Unexpected directory-sync failure after rename blocks the scope like publication failure. Failed pre-replacement persistence preserves the old generation. A failed committed publication requires `reload`, not another save.
- `onInvalidate(scope, callback)`: subscribe loaded dependents only; dispose when unloaded. All listeners run even if one fails. Hooks must synchronously invalidate local views, not start IO or recursively mutate the store. Hook failure conservatively blocks publication. Frozen-child preference versus live-security dependency selection belongs to the domain owner.
- `captureGenerations(scopes)`: after loading dependencies, returns a synchronous validity predicate. Include every relevant dependency (trust, accounts, profiles, etc.) in the owning resolver's generation tracking. After async preparation, retry unless the vector is still current; no async gap before publishing a derived view.
- `ConversationSummaryCache<Summary>`: injected strict cache-document parser; `load`, `get`, `set`, `remove`, coalesced `flush`. Missing/corrupt/unreadable caches are empty. Failed flush returns `false`, retaining pending work for retry. Call after activation/ack as recoverable work; never feed these display values into execution. No automatic scans, timers or execution fallback.

## Owning-layer responsibilities

`change` is an internal transaction builder, **not** a public arbitrary-document mutation endpoint. The domain API owns canonical editable paths, sparse changes/resets, locked-field/resolved constraints, dedicated profile/transition mutations, trust and registered old-version conversion/backup protocols. It must preserve committed transition receipts until reconciled. This core does not implement repair consent, migrations, profile resolution, runtime authorization or cross-file/SQLite transactions. It must not be used to bypass those protocols. Parsers must not strip unknown values, synthesize sparse defaults or silently migrate bytes. Domain issue classification supplies unknown-field/invalid-value diagnostics without secret values; malformed JSON, future version, absence, IO and publication failures are classified here.

Atomic replacement reuses storage-bootstrap's exclusive temp-file/fsync/rename and target mutation lock. An additional in-process queue key (never a real lock file) serializes publication/reload around that primitive without reentrant locking. Directory synchronization is added here, with explicit unsupported-platform reporting. This is not cross-process compare-and-swap: external editors can still race between digest check and rename. External edits require restart for guaranteed activation. No watchers, polling, startup enumeration, persisted last-known-good store or service integration is added.
