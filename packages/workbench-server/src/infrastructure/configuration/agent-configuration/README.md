# Agent configuration scope service (Phase 2, unwired)

`AgentConfigurationService` uses the Phase 1 contracts and scoped store. No existing consumer, composition root, permission adapter, prompt/tool description or remember-selection code is changed. JSON and validated in-memory generations are authority; the summary cache is display-only.

## Construction ports

Supply `home`, synchronous trusted `projectDirectory(projectId)` and `conversationOwner(id)` (project ID plus lead/child role), authored `builtins: Record<name, JSONBytes>`, `isProfileTrusted(projectId, path, exactDigest)`, and `captureResources()`.

`captureResources()` returns resolver `process`, `eligibleSkills`, `clampThinking`, and `referenceAvailable` options plus a synchronous `isCurrent()` generation guard. Phase 3 must supply the real model/account/resource callbacks and include their generations, trust and discovery dependencies. These callbacks must use captured memory, not poll configuration files. `invalidateResources()` explicitly invalidates loaded views when external owners publish changes. No secret values belong in these captures.

`transitionReconciled(id, receipt)` must verify that a receipt-bearing document's committed lifecycle transition is settled before an ordinary mutation. If omitted, receipt-bearing mutations are blocked; the service never infers settlement from the file alone.

Optional synchronous `publish(domain, scope)` and atomic IO ports support host publication/testing. A throwing publication hook blocks that document until explicit authoritative reload. Hooks must not start asynchronous publication work.

## API for Phase 3

- `initialize()` validates user agent/creation documents and the user/builtin profile catalog, and loads the optional display cache. It does not enumerate projects or conversations, or request conversation ownership. Invalid documents return diagnostics, not a shell-startup exception.
- `ensureLoaded(scope)`, `reload(scope)` expose scoped agent document health and immutable generations. Scope is `{scope:"user"}`, `{scope:"project",projectId}`, or `{scope:"conversation",conversationId}`. Conversation role comes only from trusted ownership. A missing conversation document blocks; an absent preference document inherits without being written.
- `getEffective(id)` returns `available` with the contracts resolution (settings, JSON-Pointer provenance and readiness diagnostics), document sources and scoped diagnostics; invalid dependencies return `unavailable`. **Available is not execution authorization/readiness**: Phase 3 must enforce applicable `model-required`, `unsupported-reasoning` and `missing-reference` diagnostics at their owning action, plus current security policy. `reasoning-adjusted` is explanatory. Applied snapshots resolve without looking up mutable catalog definitions.
- `captureEffective(id)` returns `{view,isCurrent}` for asynchronous preparation. Retry if the synchronous guard fails before publication/admission. Lead views depend on user/project/conversation generations; existing children depend on their own document/frozen preferences, plus live external resource generations. Preference edits do not invalidate frozen children. Loaded dependencies only are invalidated, with no unopened-conversation scan.
- `save(scope, mutation)` accepts contracts `{expectedRevision,expectedDigest,changes,resets}`. It enforces canonical sparse mutations/requirements, validates resolved reasoning constraints, preserves snapshots/transition receipts, persists atomically, publishes and invalidates before returning. Failed persistence leaves the old view; failed committed publication blocks until `reload`. Child preference editing remains unsupported as specified.
- `createConversation(id, completeDocument)` is a **trusted host-only** explicit initial document creation operation, revision one. It never overwrites a target. Child frozen defaults are mandatory and new child overrides must be empty. It is not missing-document recovery, a UI arbitrary-document editor, or a full launch/profile-application workflow. Phase 3 must validate the chosen current profile/trust/target and capture coherent frozen defaults before invoking it; ordinary saves cannot switch profiles or bypass a committed transition receipt. Profile/plan transition orchestration remains with its owning lifecycle.
- `loadCreation`, `reloadCreation`, `getCreationPreferences(projectId?)`, `saveCreation(scope, mutation)` operate on sparse creation preferences. `scopedModels` replaces atomically; the built-in start name is Coding (`coding`). Missing selected catalog resources remain references, not fabricated replacements.
- `profiles.get(name,projectId?,role?)`, `.list(projectId?,role?)`, `.save(scope,name,expectedDigest,definition)`, `.reload(scope,name)`, `.reloadCatalog(scope)`, `.health()` provide complete-definition shadowing and digest-only profile editing. `"missing"` explicitly creates a definition. Malformed/untrusted/disabled/inapplicable custom shadows do not fall through; unrelated malformed entries are isolated. Project trust is checked against exact bytes and is never granted by a save. File definitions have no revision metadata. Catalog directories are listed once lazily, then cached until an application save or explicit reload, not watched/polled.
- `health()` returns redacted contract diagnostics with document/path, scope identity, readable version, code, pointer, affected capability and recovery choices. Confirmation-based reset/repair and registered legacy converters belong to Phase 5; no silent repair, downgrade, default writeback or legacy fallback is added. The changed v1 paths have no supported older document version registered here.
- `getSummary(id)` never loads that conversation. `flushSummaries()` drains recoverable projection work/coalesced cache writes (also useful at shutdown); `false` reports a disposable cache failure, not configuration failure. Summaries update on lazy activation and acknowledged changes to loaded dependents. `forgetConversation(id)` removes its summary and derived view on deletion. Missing/corrupt cache means unknown list fields and never blocks execution. Lists should merge summaries with identity/history in the service, not SQL.

Paths are exactly those in the domain inventory, centralized in `AgentConfigurationPaths`: user `config/{agent,conversation-defaults}.json`, project `.nerve/config/{agent,conversation-defaults}.json`, conversation `data/conversations/<id>/config/agent.json`, user `data/agent-profiles/<name>.json`, project `.nerve/agent-profiles/<name>.json`, and `cache/conversation-agent-summaries.json` under NERVE_HOME.

No runtime consumer is switched yet. Execution admission, credential resolution, profile/plan transitions, creation orchestration, policy-domain loading and confirmed repair/migration are not implemented by this service. The optimistic digest check is not cross-process compare-and-swap; external edits require restart for guaranteed activation, or explicit health Reload for recovery.
