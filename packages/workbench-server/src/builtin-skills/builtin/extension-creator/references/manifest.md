# Manifest and definition

`src/extension.ts` default-exports `defineExtension({...})`. `nerve-ext build` writes the plain-data part to `dist/manifest.json` (with `version` from `package.json` and the SDK's `sdkVersion`) and the code to `dist/backend.js`. Never edit `dist/`.

## Fields

| Field                   | Notes                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | Folder name too: lowercase letters, digits, single hyphens, starts with a letter, at most 64. Settings, accounts and operations are keyed by it.                                                                                                                                                                                                                                                                             |
| `apiVersion`            | `1`.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `name`, `description`   | One line each, shown on the Extensions page.                                                                                                                                                                                                                                                                                                                                                                                 |
| `icon`                  | One of `blocks`, `eye`, `globe`, `image-plus`, `layers`, `workflow`, or `icon.svg` in the project root (at most 16 KB, square `viewBox`, no scripts or external references). Pages and panels have their own `icon` (any common lucide name such as `table`, `layout-dashboard`; an unknown one shows a puzzle piece).                                                                                                       |
| `enabledByDefault`      | Default of the extension's on/off switch. Use `false` for anything that reaches the network or an account.                                                                                                                                                                                                                                                                                                                   |
| `settings`              | `{ version, fields }`. Field types: `boolean`, `string` (`format: "url" \| "text"`), `number` (`min`, `max`, `step`, `unit`), `enum` (`options`), `account` (`kind`), `model` (`capability`). Each field has `label` and optional `description`, `section`, `scopes`, `visibleWhen`, `advanced`. Settings hold no secrets. Bump `version` when a field changes meaning; `migrations` is not allowed in installed extensions. |
| `accounts`              | Account kinds the extension defines: fields, a secret label, `auth` (`basic`, `bearer`, `header`) and `origins` the credential is sent to. The user adds accounts in Settings; the extension never sees the secret.                                                                                                                                                                                                          |
| `permissions`           | `network`: origins `ctx.http` may reach (`https://api.example.com`, `https://*.example.com`, `{settings.<key>}`, `{account.<field>}`; `*` means any public host and is called out as broad). `capabilities`: `models.image`, `models.vision`. Absent means no network.                                                                                                                                                       |
| `namespaces`            | `quick_script` namespaces: `id`, `summary`, `rules`, `types`, `docs`, `methods`; see `backend.md`.                                                                                                                                                                                                                                                                                                                           |
| `tools`                 | Direct tools, optionally bound to a namespace method with `method: "<namespace>.<method>"`.                                                                                                                                                                                                                                                                                                                                  |
| `limits`                | Byte limits filled into `{{limit:<name>}}` placeholders of docs and rules.                                                                                                                                                                                                                                                                                                                                                   |
| `ui`                    | `previews`, `pages`, `panels`, `themes`; see `ui.md` and `themes.md`. At most 16 per kind.                                                                                                                                                                                                                                                                                                                                   |
| `version`, `sdkVersion` | Written by the build; `version` comes from `package.json`.                                                                                                                                                                                                                                                                                                                                                                   |
| `prelude`               | Not allowed in installed extensions.                                                                                                                                                                                                                                                                                                                                                                                         |

## Agent-facing text limits

Text a model reads is checked when the folder loads; an extension over a limit is `invalid` with the limit in its diagnostics. Keep descriptions short and put detail in doc topics (`docs/*.md`, listed in a namespace's `docs`).

| Text                                      | Limit (characters) |
| ----------------------------------------- | ------------------ |
| Namespace `summary`                       | 200                |
| Each namespace `rule` (at most three)     | 300                |
| A method's leading doc comment            | 300                |
| A doc topic's `whenToRead`                | 160                |
| A doc topic file                          | 24,000             |
| A direct tool `description`               | 800                |
| An error message and its fix, at run time | 600 (cut)          |

Namespace ids must not equal a runtime namespace (`files`, `image`, `web`, `extensions`, `sdk`, `libraries`) or a global (`console`, `JSON`, ...). Account kinds, namespace ids and tool names are unique across all extensions.

## Precedence and states

Roots, first id wins: project (`<project>/.nerve/extensions/`), user (`${NERVE_HOME:-$HOME/.nerve}/agent/extensions/`), built-in. A user or project extension that reuses a built-in id is `invalid`. States: `enabled` (loaded), `pending_consent`, `incompatible` (SDK outside the supported range), `invalid` (diagnostics say why), `shadowed` (a higher root has the id).
