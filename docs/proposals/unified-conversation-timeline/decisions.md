# Decisions and deferred design

> **Status: Target decisions recorded for architecture review.** Part of the [unified conversation timeline proposal](README.md). “Decided” means selected in this target, not shipped or independently approved. Owning invariant definitions control behavior; this register records choices, alternatives and unresolved scope.

## Decided target

| Decision                                  | Selected direction                                                                                                               | Alternative rejected / consequence                                                                                                 | Owning contract                                                                                                                                        |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| History authority                         | Consolidate conversation facts into one entry ancestry and canonical selection                                                   | Retaining independent conversation/model-context trees or adding a third authority                                                 | [INV-AUTH-01](timeline.md#inv-auth-01)                                                                                                                 |
| Existing representation fate              | Journaled model-context tree/leaf and harness views become projections; run entry arrays lose membership authority               | Dropping unique context data is not consolidation: preserve meaningful facts and required provider snapshots                       | [INV-AUTH-01](timeline.md#inv-auth-01), [INV-MIGRATE-02](migration.md#inv-migrate-02)                                                                  |
| Execution authority                       | Keep authorization, attempts and required immutable snapshots authoritative separately from history                              | Full-system event sourcing or resuming from UI/model transcript approximations                                                     | [INV-AUTH-01](timeline.md#inv-auth-01), [INV-CHECKPOINT-01](execution.md#inv-checkpoint-01)                                                            |
| Active execution ownership                | One foreground owner in this version; changing execution selection fences it                                                     | Implicit concurrent foreground appends or rebasing a pending approval by matching visible text                                     | [INV-HEAD-01](timeline.md#inv-head-01)                                                                                                                 |
| Cross-conversation mutation               | One command/receipt, distinct per-conversation transitions, one database commit                                                  | Multi-owner transcript nodes or partial cross-conversation acceptance                                                              | [INV-ID-01](timeline.md#inv-id-01), [INV-COMMIT-01](timeline.md#inv-commit-01)                                                                         |
| Permission authority                      | JSON rule sets/overlays remain authoritative; exact-call evidence is durable execution state                                     | SQLite-authoritative policy with import/apply synchronization; file/database atomicity is explicitly not promised                  | [INV-POLICY-01](permissions.md#inv-policy-01), [INV-POLICY-04](permissions.md#inv-policy-04)                                                           |
| Retry safety                              | Versioned tool capabilities separate safe-repeat observations, conditional/idempotent effects and unknown/non-repeatable effects | Tool risk/name/error flags as replay permission; ordinary declared reads need not become unknown effects                           | [INV-EFFECT-01](execution.md#inv-effect-01)                                                                                                            |
| Barriers and recovery                     | Outcome, attachment and barrier contribution are distinct; uncertainty cannot silently continue                                  | Treating every stopped attempt as a satisfied barrier or using abandonment as success                                              | [INV-BARRIER-01](execution.md#inv-barrier-01), [INV-RECOVERY-01](execution.md#inv-recovery-01)                                                         |
| Child ownership                           | Parent fences attachment; independently dispatched child work continues unless explicitly cancelled                              | Implicit cancel/delete cascade or late output appended to a new parent branch                                                      | [INV-AGENT-01](execution.md#inv-agent-01)                                                                                                              |
| Client views                              | Canonical provenance, fixed historical cursors, independent delivery/reconciliation for clients                                  | Notification streams or client caches becoming transcript authorities                                                              | [INV-VIEW-01](projections.md#inv-view-01), [INV-PAGE-01](projections.md#inv-page-01), [INV-DELIVERY-01](projections.md#inv-delivery-01)                |
| Data preservation and runtime cleanliness | Migrate supported released data; target runtime implements only the new design                                                   | Default export/reset, silent history loss, dual writes or legacy runtime readers; old formats exist only at the migration boundary | [INV-MIGRATE-01](migration.md#inv-migrate-01)                                                                                                          |
| Restore and deletion                      | Explicit lifecycle fences, durable replay protection and recovery admission                                                      | Backup validity reviving old execution rights, or deleting cache/receipt state enabling repeat effects                             | [INV-RECEIPT-01](timeline.md#inv-receipt-01), [INV-DELETE-01](durable-recovery.md#inv-delete-01), [INV-RESTORE-01](durable-recovery.md#inv-restore-01) |
| Performance acceptance                    | Structural boundedness plus a small agreed responsiveness smoke                                                                  | Mandatory large benchmark sweeps or numeric fixture recipes in architecture                                                        | [INV-PERF-01](validation.md#inv-perf-01)                                                                                                               |

## Deferred design

| Topic                               | What is not decided                                                                                             | Constraints / prerequisite                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Interrupt/steer                     | Admission point, whether input joins current work or starts a new phase, and user-visible interruption behavior | A serialized steering transition may preserve [INV-HEAD-01](timeline.md#inv-head-01), [INV-CHECKPOINT-01](execution.md#inv-checkpoint-01), [INV-BARRIER-01](execution.md#inv-barrier-01) and [INV-PROVIDER-01](execution.md#inv-provider-01). Changing wait membership, request context or ownership must explicitly revise their affected clauses before implementation; it cannot masquerade as an ordinary append |
| Parallel foreground execution       | Multiple simultaneously writable paths in one conversation                                                      | Would require revisiting live-head equality/ownership and checkpoint, barrier and provider bindings above. Current implementation must enforce the decided single-owner model, not add speculative bypass flags                                                                                                                                                                                                      |
| Navigation product expansion        | Separate inspection-only UI affordances versus selecting an execution branch                                    | Current canonical selection changes use INV-HEAD-01. Viewing a fixed historical projection does not itself issue a selection command; any new navigation action must declare which operation it performs                                                                                                                                                                                                             |
| Branch labels                       | Labeling/naming UX and metadata representation                                                                  | Labels may refer to canonical entries; they cannot establish a second ancestry/selection authority under INV-AUTH-01                                                                                                                                                                                                                                                                                                 |
| Automatic history/protection expiry | Expiry policy for canonical history, tombstones and replay evidence                                             | Requires a reviewed revision to INV-BACKUP-01 / INV-DELETE-01 / INV-RECEIPT-01 / INV-RESTORE-01; no implicit TTL is authorized                                                                                                                                                                                                                                                                                       |

Ownership/applicability belongs to the shared transition boundary, not independently hard-coded consumer policies. Deferred features must preserve the owning invariants or revise their IDs' definitions explicitly. “Deferred” is not permission to weaken the current target; stable IDs are not a promise that product policy can never evolve.

## Preserved architectural assumptions

| Assumed from current architecture                                                | Target treatment                                                                                                       |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Portable local-first SQLite with external managed artifacts                      | Preserved; no database service or full-history rewrite is introduced                                                   |
| Permission precedence, rule-set identity, normalized targets and hard guardrails | Preserved by INV-POLICY-01; file failure/consent behavior is specified explicitly rather than inferred from current UI |
| Shared transport-neutral contracts and separate session/replay mechanics         | Preserved; desktop/mobile clients share the same authority and outcome rules                                           |

Current dual history trees and risk-based replay inference are **not** preserved assumptions. Their replacement is explicitly decided above. No repository's present shape can silently override a target invariant.
