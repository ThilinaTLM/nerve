## Authority and promotion audit

Production composition exposes canonical timeline, run, attempt/claim, interaction, deletion, and fixed-view services only. `scripts/lib/unified-timeline-policy.mjs` rejects migration-facet access from composition, legacy lifecycle/table vocabulary outside versioned migrations, direct parent wait-member attachment outside canonical settlement, retired runtime imports, and direct canonical-table writes outside owner persistence.

Restore and legacy-v2 migration now write the same generic home-promotion marker. The shared startup coordinator owns marker progression, sibling renames, parent-directory fsync, verification, rollback, and archival. Restore and migration retain separate evidence verifiers. Existing restore-v1 markers are parsed only by the versioned reader and normalized in memory. Legacy conversion is completed and verified in the sibling candidate; the promoted home is not opened for journal conversion. Every SQLite handle used to prepare or verify a candidate is closed before a rename.

Permission JSON remains authoritative. Repair outcomes distinguish external conflict, quarantine-created/write-failed, replacement-written/reload-failed, trust-failed, and completed reset; only completed reset permits diagnostic resolution.

## Performance protocol

All benchmark homes are fresh temporary directories on the same local filesystem class. The checked-in specification fixes seed, 1 KiB payloads, 100/2,000/20,000 history sizes, warmup/sample counts, page and batch sizes, reader/writer load, separate queue/transaction/artifact/projection/page measurements, retained-evidence accounting, and diagnostic treatment of the 20,000-entry sweep.

## Release gate

All tests use isolated temporary homes. The required gate is:

```sh
pnpm fix && pnpm check && pnpm run test:full
```
